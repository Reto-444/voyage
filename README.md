# ВОЯЖ — ресторан авторской кухни

Концептуальный сайт премиального ресторана авторской кухни. В проекте есть витрина меню, залы, события, демонстрационная форма бронирования и локальная панель управления.

**Ресторан, история, блюда, цены, вместимость, услуги и контактные данные вымышлены.** Локальная заявка остаётся в браузере, не отправляется в ресторан и не подтверждает бронирование.

## Возможности

- Главная страница с редакционной подачей, избранными блюдами, залами и фотогалереей.
- Каталог из 29 концептуальных блюд: поиск, категории, сортировка, карточки и модальные подробности.
- Разделы залов и мероприятий с демонстрационными вместимостью и стоимостью.
- Форма заявки: проверка телефона, даты, числа гостей и согласия; уникальный номер и сохранение в LocalStorage.
- Демо-панель: статистика, фильтр и поиск заявок, статусы, просмотр деталей, подтверждение удаления, экспорт CSV.
- Локальное редактирование меню и настройки отображения.
- Адаптивная вёрстка, управление с клавиатуры, Escape для диалогов и `prefers-reduced-motion`.
- Hash-навигация и сборка для GitHub Pages в подпапке репозитория.

## Технологии

React 18, TypeScript, Vite 6, Lucide React, CSS3 и LocalStorage. Серверная часть и авторизация отсутствуют.

## Структура

```text
src/
  components/   общая навигация, диалог, форма бронирования, демо-панель
  data/         каталог блюд и залов
  services/     устойчивое чтение и запись локальных данных
  types/        модели TypeScript
  App.tsx       hash-маршрутизация и состояние приложения
  Content.tsx   страницы сайта
  styles.css    дизайн-система и адаптивная вёрстка
.github/workflows/pages.yml
```

## Локальный запуск

Нужен Node.js 20+ и pnpm 9+.

```bash
pnpm install
pnpm dev
```

Для production-сборки:

```bash
pnpm build
pnpm preview
```

Готовые статические файлы появятся в `dist/`.

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите содержимое проекта в его ветку `main`.
2. В настройках репозитория откройте **Settings → Pages** и выберите публикацию через **GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` автоматически соберёт и опубликует сайт по адресу `https://USERNAME.github.io/REPOSITORY/`.
4. Имя подпапки определяется автоматически из имени репозитория через `VITE_BASE_PATH`. Hash-маршрутизация поддерживает открытие и обновление внутренних страниц без серверных правил.

Для ручной сборки под подпапку можно задать переменную окружения `VITE_BASE_PATH=/имя-репозитория/` и выполнить `pnpm build`. Локальная разработка без настройки использует корень `/`.

## Хранение и ограничения демо-версии

Заявки, изменения каталога и настройки хранятся в LocalStorage текущего браузера. Данные не синхронизируются между устройствами и могут быть удалены очисткой данных браузера. Локальная админ-панель открыта для демонстрации и **не является защищённой системой**. Форма не передаёт данные по сети.

Фотографии загружаются с Unsplash, шрифты — Google Fonts. Для работы изображений и веб-шрифтов нужен доступ к этим ресурсам. При необходимости замените URL фотографий на оптимизированные файлы проекта.
